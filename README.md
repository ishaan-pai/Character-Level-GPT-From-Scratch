# Character-Level GPT From Scratch
 
A decoder-only transformer trained at the character level on Tiny Shakespeare, written in PyTorch. Built by following Andrej Karpathy's [Let's build GPT: from scratch, in code, spelled out](https://www.youtube.com/watch?v=kCc8FmEb1nY).
 
The repo has two models: a bigram baseline (`bigram.py`) and the full GPT (`gpt.py`). Both train on the same data and generate Shakespeare-style text one character at a time, so you can see how much the attention layers actually buy you.
 
## Files
 
| File | What it is |
| --- | --- |
| `bigram.py` | Baseline model. Each character predicts the next one straight from an embedding lookup table, with no context beyond the current token. |
| `gpt.py` | The GPT model: token + positional embeddings, stacked transformer blocks, final layer norm, and a linear head over the vocabulary. |
| `input.txt` | Tiny Shakespeare training corpus (~1MB of plain text). |
| `more.txt` | A longer sample of text generated by the trained GPT. |
 
## How it works
 
**Tokenization.** Every unique character in `input.txt` becomes a token, so the vocabulary is just the character set of the corpus. `encode`/`decode` map between strings and integer lists.
 
**Data.** The encoded text is split 90/10 into train and validation sets. Batches are random windows of `block_size` characters, with targets shifted one position to the right.
 
**Model (`gpt.py`).**
- `Head`: a single causal self-attention head. Scores are scaled by `1/sqrt(head_size)` and masked with a lower-triangular matrix so each position only attends to earlier ones.
- `MultiHeadAttention`: several heads run in parallel, concatenated, then projected back to `n_embd`.
- `FeedFoward`: linear → ReLU → linear, with a 4x hidden expansion.
- `Block`: attention then feed-forward, each with pre-layer-norm and a residual connection.
- `GPTLanguageModel`: embeddings → `n_layer` blocks → final layer norm → `lm_head`. Weights are initialized from a normal distribution (std 0.02).
**Training.** AdamW with cross-entropy loss. Train and validation loss are averaged over `eval_iters` batches and printed every `eval_interval` steps.
 
**Generation.** Starting from a single zero token, the model repeatedly crops the context to the last `block_size` characters, takes softmax over the final position's logits, and samples the next character with `torch.multinomial`.
 
## Hyperparameters
 
| | `bigram.py` | `gpt.py` |
| --- | --- | --- |
| Batch size | 32 | 64 |
| Context length (`block_size`) | 8 | 256 |
| Training iterations | 6000 | 5000 |
| Eval interval | 300 | 500 |
| Learning rate | 1e-2 | 3e-4 |
| Embedding dim (`n_embd`) | — | 384 |
| Attention heads | — | 6 |
| Transformer layers | — | 6 |
| Dropout | — | 0.2 |
 
The GPT config comes out to roughly 10.8M parameters (the exact count is printed at startup).
 
## Running it
 
Requires Python 3 and PyTorch.
 
```bash
pip install torch
python bigram.py   # baseline
python gpt.py      # full model
```
 
Both scripts use CUDA if it's available and fall back to CPU otherwise. The bigram model trains in seconds on CPU; `gpt.py` is realistically a GPU job at these settings. If you're on CPU, drop `n_layer`, `n_embd`, and `block_size` to get it running in reasonable time.
 
When training finishes, each script prints 500 generated characters. To write a longer sample to `more.txt`, uncomment the last line of `gpt.py`.
